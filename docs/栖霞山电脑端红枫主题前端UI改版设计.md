## 1. 本轮方向与功能边界

用户否定v3的沉闷、老气观感，要求“有活力一点、视觉对齐、重新生成”。本轮以v2的通透旅游门户为视觉基础，重新整理亮色层次、图形、字体和对齐；**v3视觉稿不再用于实施，改以本版审核结果为准。**

三个主入口仍为AI问答、地图导览、游记海报，AI默认。首页用六个常用快捷入口解释已有功能：AI问答、地图导览、景点讲解、天气红叶、游记海报、厕所与大门；它们仍归属原来的三个页面，不增加业务模块。

配色使用明亮青蓝、薄荷、淡紫与小面积珊瑚红，背景恢复清透浅灰蓝。红枫由原景观图和品牌点缀传达。撤下v3的宋体大标题、米色底、灰橄榄绿和整条暗色磨砂栏；不再把“克制”理解成压低全页饱和度。

低频按钮从主界面移入分组更多，功能保留清单继续见第5节。取消回答、停止定位、停止朗读、失败重试和退出应用不能藏进不易发现的位置。不修改模型、接口、景点/设施坐标、路网、导航判定或海报输出规则。

本轮仍只交设计文档、图片和独立交互原型。原型中地图为已有截图，问答为明确标注的示例，选图只展示文件名；没有真实模型、GPS、上传、规划、海报生成或PNG导出。用户审核通过后才改原项目。

继续采用animate的频率与用途判断、animation-performance的属性约束、apple-design的反馈和可访问性、emil-design-eng的组件细节；animation-vocabulary仅统一术语。animate-expo的原生技术不适用于当前HTML网站；aigc-reduce只检查文档套话，不改产品AI提示词、事实或接口。活力来自色彩、图形和排版，不靠持续飘叶、机器人浮动或滚动劫持。

## 6. 保持功能和内存状态的实现方案

### 6.1 为什么不能只改CSS

两个页面通过`web/js/session.js:3`中的`qixi_sid`共享服务端行程，但聊天消息是`app.js:170`起追加的DOM，现有首页没有聊天历史回填。海报照片、候选和objectURL存在`poster-app.js:16`起的页面内存中。普通跳转、iframe换src或重新挂载都可能销毁这些状态。

因此本轮实现必须增加**界面导航壳层**；它不是新的业务后端。若只保留旧整页跳转，即使共享sid，也不满足已确认的Q6。

### 6.2 推荐：问答/地图同文档，海报同源持久工作区

1. 顶层保留问答DOM及唯一Leaflet实例，用独立`activeView=chat|map|poster`切换；正常首次打开为chat。该入口另有`intro/conversation`两种纯界面状态：首次无对话展示可直接输入的门户初始态，首次提交或已有消息时显示工作态；不新增业务页面、请求或永久存储。标签与状态切换不调用`QixiMap.setMode()`、`reset()`、新行程或取消接口。
2. 海报首次进入时加载同源`/poster.html?embedded=1`工作区，之后保留iframe实例与src；隐藏而不销毁，使照片、候选和任务仍在原内存。隔离现有全局变量、CSS及固定导出舞台。
3. 海报内嵌时隐藏重复站点顶栏，使用父壳层的三个入口与退出；不移除工作台功能。旧顶级`/poster.html`深链可在启动业务脚本前转到`/#poster`，内嵌条件需同时检查参数和确实处于父框架中，避免循环跳转。
4. 顶层采用hash/history的同文档切换，支持浏览器前进/后退；入口切换不执行整页导航。直接进入明确地图/海报深链时按该入口打开，普通首页仍默认问答。
5. 同源桥接只传可见性、任务摘要、代际/行程变更提示和退出到其他视图请求，不传Key、照片base64或创建第二套会话。使用postMessage时同时校验`event.origin`与`event.source`，只接受枚举动作；不使用`*`接收不明请求。
6. 内嵌策略须保留原来的用户文件选择、拖放、剪贴板、dialog、音频及PNG下载能力；不随意添加阻断这些功能的sandbox策略。不得为内嵌放宽成任意来源可嵌入。
7. 全局任务条按真实状态出现：回答中可取消；定位中可停止；朗读中可停止并返回讲解；海报/照片识别任务可返回查看。仍调用原处理器，不复制业务请求、编造新取消能力或展示假百分比。停止朗读必须走原`stopVoiceBtn`逻辑，切入口不自动重播或重设`voiceOn`。
8. 工作区必须有ready握手。初始化完成后对账父层当前sid/generation及最后已处理代际；加载期间发生的新行程不能漏掉。`qixi_epoch`的storage通知与bridge通知按同一代际幂等处理，不因重复通知反复失效或用旧结果覆盖新行程。
9. **到点状态由父向导唯一消费并分发。** 当前`GET /api/state`会执行`_sync_arrival()`，不是无副作用的读取；内嵌海报若自行请求，可能先取走一次到点事件。内嵌模式的初始化/状态同步应向父层索取必要快照，父层通过原`refreshState()`处理到点再分发generation、revision、visited等必要数据，不新增第二个到点轮询消费方。独立兼容路径仍按既有行为处理，不改服务端接口。

**实施第一阶段先做可行性验证。** 若同源保活无法满足选择文件、导出、焦点、后台暂停或代际隔离，不得静默退回整页跳转后宣称完成；应在不改业务规则的前提下调整壳层，并更新本文的技术记录。

### 6.3 切换与后台行为

| 场景 | 应有结果 |
| --- | --- |
| AI→地图→AI，回答进行中 | 原SSE继续，同一个请求；不重发、不重置文本，任何页可取消 |
| 地图→AI/海报，定位进行中 | 同一顶层document仍前台，原订阅保留；全局显示精度/暂停状态和停止入口 |
| 到点讲解正在朗读时切入口 | 原播放不中断或重播，任何入口均可停止；新到点仍沿原播报判定 |
| 整个应用切后台或pagehide | 仍按现有规则停止定位，不做后台或锁屏导航 |
| 海报→其他入口→海报 | 照片objectURL、手工点位、候选、当前选择及未完成任务不因切换丢失 |
| 再次显示地图/画布 | 容器有实际尺寸后适配；保留中心、缩放、已选地点、路线和预览选择 |
| 再次进入海报时行程已变化 | 从父向导同步必要状态快照或明确提示；不另行消费到点事件，不自动调用可能重生成日记/产生模型费用的刷新流程 |
| 开始新行程 | 原服务端generation规则继续生效，通知保活工作区失效旧候选/请求；不擅自扩大成清空全部照片 |
| 模型设置改变 | 延续原配置版本及请求规则；不因新壳层再触发一次测试或生成 |
| 刷新、关闭程序、进程崩溃 | 仍有原先内存草稿边界，不新增永久保存，不宣称能够自动恢复照片 |

地图首次隐藏时不得以零宽容器初始化错误视野。可在首次激活且容器布局稳定后初始化；若沿用既有初始化则需验证隐藏尺寸处理。再次显示仅做必要的`invalidateSize({pan:false})`，不能每次全览、重建地图、重复订阅定位或清路线。

海报显示后通知既有`fitStage()`重新计算预览；不修改`#stage`内容与导出变换。键盘焦点不得留在隐藏工作区，海报数字快捷键不能在问答输入时误触。每个DOM ID在对应文档内唯一，不能复制旧节点来获得第二个事件处理器。

旧识别、日记、回放或候选失效，表示不得再把旧结果写入当前界面；不等于服务器任务或模型消耗已经停止。现有`/api/recap`有受保护的服务端任务，本轮不新增虚假的“取消海报云任务”按钮，也不把本地abort说成云端取消成功。此处保留原业务语义，只明确任务状态。

## 7. 响应式与可访问性

| 可用宽度 | 布局 |
| --- | --- |
| ≥1280px | 首页六项快捷功能带，AI主区＋今日游览；地图左规划右大图；海报三列 |
| 1024—1279px | 缩小非内容间距，海报候选转下方，地图工具可换行 |
| 768—1023px | AI摘要转下方，地图规划可上移，海报保留清晰任务顺序 |
| <768px | 同一网页纵向布局；三主入口另起一行，更多和退出仍可见，设施/停止/重试可达 |

设计重点覆盖1920、1440、1366、1280、1024、800、640、390、320宽，并检查200%文本缩放；正式实施还需在1280×720和1366×768检查可用高度与滚动。窄窗口不是新的安卓需求。

主入口用原生按钮或链接；“更多”“更多问题”“来源”等采用原生`details/summary`或已有可访问组件，照片大图使用原生`dialog`。不用无语义div手写弹层，不因美化引入React/Expo或动画库。更多关闭后焦点回到触发入口；大图支持Esc及关闭后焦点返回。隐藏工作区不能留下Tab焦点或继续处理海报快捷键。

键盘切换与快捷操作即时生效；动态状态用克制的`aria-live`，流式文字不整段反复播读。触屏不靠hover发现功能，按下反馈只影响呈现，提交仍在原click/submit阶段，不能改成pointerdown就发请求。

`prefers-reduced-motion`减少位移和缩放；`prefers-reduced-transparency`将顶栏改为实底；`prefers-contrast: more`使用实底与明确边界。不支持偏好查询的浏览器使用默认可读实底兜底，不能把玻璃模糊当成可用前提。

## 8. 动效、性能与不等待原则

### 8.1 先决定是否动画

| 元素/频率 | 用途与决定 | 参数和降级 |
| --- | --- | --- |
| 三入口切换、快捷键、高频列表选择 | 即时切换；不横向滑屏，不错峰入场 | 0ms；保留状态与焦点 |
| 流式回答、路线文字、导航状态 | 内容优先，不给数据增加二次打字或跳动 | 到达即按原流程显示，无额外等待 |
| 指针按下主按钮 | Feedback；确认已按下，原click/submit时机不变 | CSS transform `scale(.97)`，120ms，`cubic-bezier(.23,1,.32,1)`；抬起/取消即复位，键盘与减少动态不位移 |
| 更多、图层、来源等展开 | 原生即时展开；阅读与操作更直接 | 无高度动画、无关闭倒计时 |
| 偶发照片大图 | Spatial consistency；对同一图片的出现/收起给予短提示 | 原生dialog＋WAAPI，opacity与scale(.97↔1)，打开200ms、指针关闭160ms，同一路径；键盘/Esc、减少动态、无WAAPI时即时 |
| 地图平移、缩放和跟随 | 沿用Leaflet交互；不包裹额外CSS变换 | 减少动态时程序化平移、全览、跟随关闭位移动画，导航计算不变 |
| 既有日记回放 | 保留原回放功能和正常模式时序 | 减少动态可直接显示同一文字；结束不保留无意义光标循环，不改变日记内容 |

动画不作为开始请求、接收SSE、规划路线或允许取消的前置条件。不得用`setTimeout`等动画结束后才发业务请求，也不得禁用全页输入等待转场。照片弹层的关闭动画可被Esc中断；从当前呈现值继续，不从逻辑终点跳变。按下反馈不作用于Leaflet缩放按钮、pane或导出舞台。

### 8.2 根据现有代码制定的检查

现有`web/poster/poster.css:30`过渡背景/描边，属于小范围重绘，不能仅凭代码称为掉帧；新外壳不复制成大面积颜色、阴影或模糊动画。`poster.css:70`有持续光标闪烁，应在回放结束后停止。`map-osm.js:249/298/347`的部分`fitBounds/panTo`未明确统一减少动态处理，实施时要补呈现偏好分支，不能改路线或定位判定。

这些是源码检查，不是已测得的性能故障。当前版本没有证据支持“已稳定120fps”的结论。

### 8.3 性能预算与验证条件

新动效只用`transform/opacity`，CSS优先，偶发程序控制用WAAPI；不新增motion库、每帧React状态、继承CSS变量驱动、`transition: all`、永久`will-change`或模糊半径动画。首页导航胶囊不依赖背景模糊；复杂场景用稳定实底，不以玻璃材质影响输入。

艺术图作为本地静态资源；正式包按实际显示尺寸压缩，目标单张≤700KB，并固定宽高比例。当前原型仍复制v2原图以保持素材一致，尚未将图片压缩写回产品。只保留一张主图，不加外部字体或图库CDN。

审核后对真实程序记录：同一浏览器、1440×900、60Hz及4倍CPU节流各运行20次指针开关大图/切换/发送；DevTools记录长任务、Layout/Paint与丢帧，业务数据和请求次数做前后对照。16.7ms/帧是60Hz参考预算，120Hz约8.3ms，不作为未实测的保证。目标：常规切换不新增动画等待，反馈即时，20次内无由新UI动效引入的>50ms长任务；异常需关联录制归因，不能用阈值代替功能验收。

还需用一台普通集显Windows 10/11电脑实测地图缩放与SSE/海报忙时响应。桌面节流不能模拟弱GPU，不能以本轮静态截图或无头浏览器代表真机流畅。

### 15.4 保活、桥接与任务边界

桥接频道`qixi-ui-v1`严格核对`origin`、`source`、`sid`。子→父允许`ready/request-state/busy/back`，父→子允许`snapshot/active/epoch/unavailable`。快照只传代际、到访和epoch，不传照片/Key；快照可复用父级当前结果，缺失才走父级原刷新流程。内嵌海报不请求`/api/state`，避免额外消费到点事件。

父级成功开始新行程后发送epoch；子工作区按epoch/generation幂等失效旧候选、识别和日记结果，保留照片；storage与桥接使用同一入口。行程后续变化会提示刷新文案，不擅自调用收费生成。子工作区恢复仅适配预览尺寸，数字快捷键仅在活动工作区且非输入框生效。

回答取消仍调用原取消处理，测试覆盖两条在途回答全部取消；换页不重发。整个应用隐藏时沿用原暂停定位规则，内部切页保留同一订阅。照片识别/日记/海报按原任务流程继续，UI只显示任务状态；没有新增虚假的云端取消承诺。
