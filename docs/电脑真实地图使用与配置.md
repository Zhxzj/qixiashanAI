# 电脑真实地图使用与配置

## 配置

1. 双击便携EXE（或按项目开发入口启动），在地图卡片点「地图设置」。
2. 到高德开放平台控制台创建应用和 **Web端（JS API）** Key，取得该Key对应安全密钥。需要账号、身份核验或套餐选择时由本人完成，不向对话发送凭据。本版本不要求另填Web服务类型Key。
3. 按高德控制台当前规则配置合法来源及权限，核实JS API、POI搜索、步行规划的额度与使用许可；具体是否可用以本人账号为准，不擅自启用收费。允许本机实际使用的127.0.0.1端口（8017，冲突回退8018/8019），再通过页面填写并保存。
4. 配置在当前Windows用户 `%LOCALAPPDATA%\QixiGuide\config\config.json`，地图安全密钥不回显，地图与模型Key分开。发给别人前不要拷贝该用户配置；构建产物不附带你的Key。
5. 默认使用官方在线服务。地图、Loader和瓦片需要联网；本机代理只处理有限的地图服务接口。若SDK控制台报具体来源/权限错误，按官方控制台检查，不关闭浏览器安全设置。

本地配置可被电脑所有者提取，不能替项目方保护统一商业凭据。需要项目方免配置发给所有收件人时，应另设计受控远端服务和额度策略。

## 地图与规划

搜索名称，点候选查看来源和地址，设置起终点，也可点地图选起终点；支持最多5个途经点。点「规划步行路线」，地图和会话使用同一完整高德路径。规划失败不会补直线或回退旧草稿。

「查询主要景点」会在你确认后，按现有景点名称逐项查询高德，只采用范围内唯一同名匹配的坐标，列出缺失/歧义项。红色“景”为查询景点，蓝色“厕”为你导入的厕所；不会把原草稿坐标搬到真实底图。搜索结果仍需核对入口和现场开放情况。

高德返回不代表现场一定开放，也不保证最短、无台阶、红叶或遮阴优化。对话中的路线意图会查询目标，需在地图核对并点规划；同名或缺失时要自行选点。起点变化后需重新规划，旧路径仅为上次结果。

聊天正在更新行程时，改变地图模式或提交新路线会提示先取消回答/等待完成，不在后台积压旧写操作；拖动、搜索、位置更新和停止定位不必等模型回答。开始真实游览前建议点「开始新行程」，避免混入已有演示记录。

拖动后停止自动位置跟随；可重新开始定位恢复跟随。全览只在规划成功或用户点击时触发，轮询不会重置缩放。景点层是本次查询候选，不代表景区全部景点；高德底图自带标注与项目自有数据分别对待。

## 定位

点「开始定位导航」后允许浏览器和Windows系统定位。浏览器WGS84坐标会发送至高德转换一次为GCJ-02；聊天时当前位置也会发送至已配置模型，用于回答位置问题。无GPS电脑不能保证米级精度。

页面显示精度和采样时间。只有新鲜度≤15秒且精度≤25米的稳定设备样本才进行实时判断；过期/低精度/明显跳变暂停进度与到点。偏离持续8秒再提示，不自动频繁重新算路。到点讲解要求匹配的高德景点、35米内（含精度余量）、驻留8秒及新样本确认；只有投影到路线末端不等于已到达。

手动起点可以预览路线，不代表你在该处。页面隐藏、停止、重置使定位失效，返回后需主动重开；浏览器故障时后台最迟随样本15秒陈旧停止判断。聊天触发重规划可能撤销导航，界面会在下一上传时停止并提示重开。

程序不保存连续设备轨迹，结构化工具坐标、当前高德路线及POI仅进程内使用，不落会话SQLite；用户原话、模型正文、日记和访问记录仍按原会话规则保存，可能包含用户提及或模型描述的位置信息。正式数据使用权限仍需核准。

## 演示与厕所

控制台跳点/前进会明确切换「演示草稿」，不把草稿经纬度叠在真实地图上。返回真实地图需重新规划。原草稿文本与照片地名关联不等于已完成实地校对。

厕所暂为空集。页面可下载JSON填写模板，必填唯一ID、名称、经纬度、GCJ-02、来源和核实日期；先校验预览再确认替换。不要从现场牌图像素猜坐标，未知坐标系先核实转换。未知开放时间/无障碍属性可填null。

两张用户照片仅辅助名称和道路关系核对：虎山服务站、虎山瀑布、碧云亭、读枫阁、揽秋湖、叠浪岩、德云亭、桃花扇亭、桃花涧等为候选，不保证抄录无误；没有高德或现场坐标核实前，不作为导航点。牌上「您所在位置」不能当设备位置。

## 本次验收边界

用户选择稍后配置地图Key，所以真实高德连通、账号权限、园内步行覆盖、现场精度与联网P95尚未验收。自动化测试的模拟高德和模拟位置只验证程序契约。配置后还需核对典型园内路线、入口/封闭情况和电脑真实定位，再判断能否用于实际游览。
