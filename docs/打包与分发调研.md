# 打包与分发调研（2026-10-15）

要解决的问题：**很多评审/朋友的电脑上没有 Python**，怎样让对方"双击就能用"。

## 一、三条路线对比

| 路线 | 对方要什么 | 体积 | 启动 | 风险 |
| --- | --- | --- | --- | --- |
| 让他装 Python | 装 Python 3.10+ | 小 | 快 | 评审机常装不了软件，直接出局 |
| **免安装包（便携 Python）** | **什么都不用** | 150–200MB（zip 后约 60–80MB） | 2–5 秒 | 最低，最推荐 |
| 真沙箱：VM / Docker / 云 | 管理员权限 / Docker / 公网 | GB 级 | 慢 | 赛前别碰 |

> 备注：PyInstaller 是另一条常见路线，但它目前**还没有支持 Python 3.14** 的轮子
> （我们的开发环境是 3.14），所以首选便携 Python；等 PyInstaller 支持了可以再补一条。
> 便携 Python 其实更接近"沙箱"的含义：解释器、依赖、程序全部装在一个文件夹里，与对方系统隔离。

## 二、推荐路线：便携 Python 免安装包

```
枫客松-小栖-demo-free\
├─ 启动.bat（或 start.bat）  ← 对方只需要双击这个
├─ app\                      ← 我们的程序（含 agent / 七工具 / 海报 Skill / 音频 / 数据）
├─ runtime\python\           ← 便携 Python（不含系统依赖）
├─ runtime\packages\         ← fastapi / uvicorn / httpx / Pillow
├─ 使用说明.md / 卸载说明.txt
```

构建（在你的机器上，需要一次联网）：

```bat
scripts\build_portable.bat
```

产物在 `dist\枫客松-小栖-demo-free\`，把它压成 zip 发给别人即可。

## 三、为什么不用真沙箱

- **Windows 上"沙箱"= 容器/虚拟机**：需要 WSL2 或 Hyper-V，要管理员权限、要重启、
  要下几个 GB 的镜像；对方电脑未必允许。
- 你的目标只是"让对方双击看到网页"，容器带来的隔离收益为 0，成本却极高。
- 演示当天现场机器同样面临"不给装东西"的问题——便携包在哪台机器上都是双击即用。

## 四、注意点（构建时已自动处理）

1. **路径**：程序全部走 `app/runtime.py` 解析资源路径，源码 / 便携包两种布局都能跑；
2. **配置存放**：优先写在程序目录（绿色包可随身带走），目录只读时自动退回
   `%LOCALAPPDATA%\QixiGuide`；
3. **端口**：包内启动器自动在 8017–8022 里挑空闲的；
4. **浏览器**：优先 Edge/Chrome 的 `--app` 窗口（像桌面应用），关窗口即停服务；
5. **网络**：对话与视觉识别要联网（DeepSeek）；天气有本地兜底；地图、海报、语音全离线可用。
