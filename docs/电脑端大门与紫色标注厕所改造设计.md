## 3. 截图配准依据与误差边界

### 3.1 方法与检查结果

已完成只读分析，未改图片或项目文件：

1. 识别紫色主色 `RGB(163,73,164)`，共1001像素、12个独立连通标记，未将同一个圈拆成多个厕所。
2. 用截图红色景点标记中心和本地 OSM 对应 WGS84 坐标配准；按现有图标中心与锚点关系处理约0.75截图像素的偏移。
3. 经度与 Web Mercator 纬向分别作线性拟合，再将纬向反投影为 WGS84 纬度。不能把整张截图的纵向像素直接等比例换算成纬度，也不能将 WGS84 再转一次 GCJ-02。
4. 10个控制点：凤翔峰、读枫、虎山、德云亭、桃花扇亭、珍珠泉、幽居庵、待月亭、如來堂、栖霞寺。
5. 2个独立留出点：碧云亭、了凡问道，未参与拟合。

| 控制点 RMS 残差 | 约0.55截图像素 |

## 5. 地图展示与校对交互

### 5.1 浏览

- 工具栏分别提供“厕所”“大门”显隐开关，默认开启；未定位的大门不生成地图标记。
- 厕所使用清楚可辨的WC或厕所图标，大门使用门图标，与现有红色景点标记区分。颜色之外同时提供形状、名称和可访问标签。
- 搜索包含已定位设施，类别和来源明确；待确认大门可在管理列表找到并进入点选。
- 点击图标或搜索结果时平移、适度放大、高亮，在现有详情位置展示名称、状态和操作；不自动改变起终点、途经点或当前路线。
- 景点详情与设施详情共用侧栏区域，宽窗口在右侧，窄窗口在地图下方。保留关闭、返回全览及键盘操作。

### 5.2 校对

流程为：**选择设施 → 进入校对 → 地图点选 → 预览新旧位置 → 确认保存 / 取消**。

1. 普通浏览点击地图、拖动地图或点击图标都不能写位置；图标默认不可拖动。
2. 校对模式显示所选名称、操作提示与显著的取消按钮。临时标记独立于已保存标记；切换条目先处理未保存预览。
3. 点击只更新预览，不立即落盘。取消、关闭或按Esc清除预览，不产生保存请求。
4. 点选坐标直接取 Leaflet WGS84 经纬度，检查有限数值及景区数据范围，不要求用户手填经纬度，不自动移到道路上。
5. 保存成功才更新正式标记和本机版本；失败保留原位置，显示可重试错误，禁止显示虚假成功。
6. 改过的厕所可“恢复截图位置”，需明确确认。大门没有默认坐标，恢复默认后回到待确认列表。
7. 用户点选后状态为“用户校对，未现场测量”，不能自动晋升为“现场核实”或“入口通行已核实”。

选点时暂停镜头自动跟随，避免地图移动导致误点，但不伪造或替换设备定位。若保存改变了当前路线使用的目标设施，应将该设施路线标为需重新规划，停止旧路线的到点判断；其他路线不因普通浏览或无关设施校对而重置。

## 6. 导航适配与真实定位边界

### 6.1 位置、路网端点、入口分别表示

设施标记保留其真实输入位置，包括截图换算中心或用户点选坐标。规划结果另列实际可到达的**路网终点**，不得通过移动厕所标记掩盖差距。

对尚未核实入口的厕所和大门，操作文案为“规划到附近道路”，而非“精确导航到门”。规划只使用已有路网的实际连接，返回并展示：设施位置、路网终点、两者直线距离、入口/连接是否核实、路线版本。

直线距离仅说明空间间隔，不是剩余可走距离，不计入可通行路线里程、预计时间或自动引导。示例提示：“路线到此结束；设施标注位置距此约XX米（直线距离），后续通行请现场确认。”不画实线、虚线等可能被误认为可走路线的连接线。

继续沿用现有端点匹配的距离上限与图连通检查；上限不足、不同连通分量或路径不存在时明确规划失败，不增加阈值强行接入，也不返回直线代替路径。距离近不代表道路可通行，不因自动匹配到节点就标记通行核实。

### 6.2 到点与行程

- 允许提示“已接近本路线的路网终点，设施入口待确认”。
- 未核实入口不得触发“已到厕所”“已到大门”的播报、设施完成状态或景点讲解到点事件。
- 只有以后补齐入口坐标和接入依据，经过独立校验，才可考虑启用设施到达判断；本轮点选确认不解锁该能力。
- 路线绑定设施ID、位置版本和路网版本；设施位置修改或路网版本不一致时，旧判断失效并要求重新规划。

### 6.3 实时定位

保留现有 WGS84 定位链路，不将截图、手动起点或设施点选当作电脑当前位置。不进行重复坐标转换。现有精度≤25米、样本年龄≤15秒以及序号、异常跳变等检查继续适用。

浏览器拒绝定位、无定位能力、精度不足或样本过期时，暂停实时到点与偏离判断，允许手动起点浏览路线。显示精度和采样状态；手动模式不能声称提供真实跟随。编译及模拟测试不能证明电脑现场定位精度。

## 7. 数据、接口与本机保存设计

### 7.1 数据分层

拟新增 `app/data/map_annotations.json` 保存只读基线：12条厕所、有名称无坐标的2条大门，以及配准元数据。设施逻辑从独立服务加载和校验，避免把地理事实写死在JS或Python条件分支里。

本机修改通过 `user_path("config/map-annotations.json")` 保存，默认位于 `%LOCALAPPDATA%\QixiGuide\config\map-annotations.json`；继续支持既有 `QIXI_USER_DIR` 配置。覆盖以稳定ID逐条合并，不能整表覆盖误删其他设施，也不写进EXE临时解包目录或源码资源。

| 字段 | 约束 |
| --- | --- |
| `id` | 如`toilet_T01`、`gate_west`、`gate_south`，稳定且唯一 |
| `category` | `toilet`或`gate` |
| `name` | 有长度限制；界面按纯文本输出 |
| `coord` | `[lat,lng]`、WGS84；待确认大门可为null |
| `position_status` | `screenshot_approximate`、`user_confirmed`、`pending` |
| `source` | 本次图片哈希、标记ID及像素/配准记录，或本机点选确认记录 |
| `revision`、`updated_at` | 并发保存校验与修改时间；时间不冒充现场核实日期 |
| `access_verified` | 本轮均为false；客户端点选不得写true |

原始来源不可因校对覆盖而消失，应同时保留基线和本机修订信息。开放时间、无障碍、现场精度不明时使用null/未知，不能填默认肯定值。

### 7.2 新增接口契约（拟定）

不改变冻结的聊天、SSE、工具、会话及原有景点接口。现有 `/api/map/facilities` 和旧导入格式保留兼容，不把“用户校对”塞进旧的“核实日期”字段。

| 接口 | 行为 |
| --- | --- |
| `GET /api/map/annotations` | 返回合并后的条目、基线版本和修订号；含未定位大门供管理列表展示 |
| `POST /api/map/annotations/preview` | 校验ID、坐标、修订号，返回预览；不写文件 |
| `POST /api/map/annotations/save` | 只保存已知条目的坐标修订；要求预览对应内容与当前修订号一致 |
| `POST /api/map/annotations/reset` | 重置指定ID的本机覆盖；保留其他条目 |
| `GET /api/map/annotations/export` | 下载带schema版本、来源、基线及覆盖的JSON，供备份或人工审核后合入包 |

请求只接受规定字段、JSON类型、已知ID、有限经纬度和景区范围内坐标。不能通过该接口新增任意路径、改分类、改来源、写入通行核实标记或编辑道路。接口沿用本机服务的访问边界，写操作验证同源请求，限制请求体大小；不接收客户端文件路径。

保存采用同目录临时文件、成功落盘后原子替换，并对修订检查与替换加锁。重复保存相同内容不制造额外修订；旧修订提交返回409，校验失败返回422，磁盘异常返回明确错误。损坏文件要提示并保留备份，不能静默覆盖或把它当作空文件。有效覆盖可以按ID隔离校验，未识别条目留在诊断记录中，不隐藏数据丢失。

导出不包含模型Key、设备定位轨迹、聊天或照片。重启后使用同一用户目录读取；换电脑需要用户保管导出文件，本轮不承诺云同步或新增一套通用导入系统。

### 7.3 规划结果契约补充

在地图接口变更记录中先定义：设施ID及修订、目标坐标、实际路网终点、直线间隔、接入状态、路网版本。服务端依据设施记录判定未核实状态，不能信任浏览器提交的`access_verified`。规划提交必须保持原有会话、序号及版本保护。

旧的普通景点路线保持原行为；设施附近道路模式单独标明语义。无匹配终点时返回失败，不产生“可用路线”。

## 8. 景点照片排版

详情顺序改为：**景点名 → 可放大的实景照片 → 大字简要介绍 → 小字详细介绍 → 默认折叠的资料来源与核实状态**。

照片下方不再显示照片标题、作者、日期、许可或“历史照片”等单独说明段。照片来源链接、作者、许可、拍摄日期及历史状态说明放在同一个默认关闭的`details`来源区，保留内容和可点击链接；不删除原数据文件和随包许可台账。

大图弹窗显示照片和关闭操作，不在照片下方显示说明；保留图片alt、可访问名称、Esc关闭、焦点返回及键盘操作。来源从侧栏折叠区查阅。没有照片、加载失败以及简介/详述的现有降级继续可用，不临时调用大模型生成图文。
