## 一、新电脑首次上手

1. 安装 Git for Windows（自带 git 命令和登录弹窗）。
2. 打开终端，克隆仓库：

   ```bat
   git clone https://github.com/joeyl3526-cloud/qixi-guide.git
   ```

3. 进入目录，双击 `启动.bat`（或 `start.bat`）——首次会自动建 Python 环境、装依赖，之后双击即用。
4. 动手改代码前，先读 `docs/指导文件/` 里的三件套（总纲 + 海报办法 + 语言守则）。

## 二、日常同步（开工先拉，收工前推）

```bat
git pull                 :: 开工：先把队友的改动拉下来
git add -A
git commit -m "改动说明"
git push                 :: 收工：把自己的改动推上去
```

原则：**小步提交、勤同步**。半天以上的改动不要憋着，先推一次再说。

## 三、分工与边界

- 目录分工沿用仓库 `AGENTS.md`：后端（`app/`、`scripts/`、`tools/`）与前端（`web/`）尽量分开改；
  需要跨目录改动时，先在 `docs/` 或 Issue 里写一条说明。
- 同一个文件别两个人同时改。确实要改同一个文件时，先发 Issue 打个招呼、约好顺序。

## 四、什么时候开分支 / 提 PR

- 小改动（改文案、修小 bug）：直接在 main 上提交推送。
- 大改动（动架构、动接口、一次改很多文件）：开分支 + 提 Pull Request，请另外两人看过再合并。

  ```bat
  git switch -c feature/你的主题
  :: ...改完...
  git push -u origin feature/你的主题
  ```

  推送后到 GitHub 网页点 "Compare & pull request"，写清楚改了什么、为什么改。

## 五、用 Issues 同步消息

- 任务、bug、想法、要对方确认的事，都开一条 Issue（仓库页 → Issues → New issue）。
- 完成后自己关闭，并写一句结论。超过一天没回应的 Issue，直接微信/电话催。

## 六、不要提交的东西

- 大文件不进仓库：`dist/`（打包产物）、`.venv/`、`node_modules/`、日志——已在 `.gitignore` 里，不要强行 `git add -f`。
- API Key、密钥、个人隐私信息不要写进任何文件。`config.json` 已被忽略，但密钥也不要留在代码里。

## 七、遇到冲突（merge conflict）怎么办

- 别慌，**不要**乱删文件。`git status` 会列出冲突文件。
- 打开冲突文件会看到 `<<<<<<<` `=======` `>>>>>>>` 标记：把两边内容商量着合好、删掉标记，
  然后 `git add` → `git commit` → `git push`。
- 拿不准就把冲突文件原样发到群里或 Issue，由仓库主统一处理。
