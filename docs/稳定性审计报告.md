# 稳定性审计报告（全链路崩溃概率排查）

日期：2026-10-15 · 范围：一键启动链（源码版）× 免安装分发链（便携包）× 运行期服务端 × 素材脚本
方法：逐文件代码审查 → 沙箱复现 → 修复 → 回归测试（每个修复都配了可重复运行的验证）

## 一、结论摘要

排查发现并修复了 **3 个“发到别人电脑必翻车”级别的问题** 和一批中小坑，目前两条分发路径都过了回归测试：

1. **新电脑首次安装会崩**：`start.bat` 用“系统 Python”跑安装脚本，依赖却装在 `.venv` 里，
   同一进程继续 `import app.*` 时找不到依赖（就是之前那条 `ModuleNotFoundError` 的同类问题）。
   → 已修：安装完成后**自动切换**到 `.venv` 解释器重跑，并加了回归测试。
2. **免安装包三重损坏**：内置解释器下成了 **free-threaded（无 GIL）构建**（依赖的二进制扩展根本无法加载）、
   `start.bat` 里 **launcher.py 路径和 PYTHONPATH 都写错**（双击静默无反应）、依赖清单**缺 Pillow**。
   → 已修：下载规则跳过 free-threaded + 解包后 GIL 探针 + 修正启动器 + 补齐依赖；
   打包链接尾再加“装完必须能 import”的探针，坏包不可能再出厂。
3. **Python 安装不完整/网络差时的连锁崩溃**：pip 缺失、镜像不通、venv 搬家损坏这几种常见情况原来都会直接失败。
   → 已修：pip 自修复、venv 损坏自动重建（改名保留现场）、依赖本地可用时**离线继续启动**。

## 四、兼容性结论

**目标机器两类：**

| 机器 | 方案 | 要求 |
| --- | --- | --- |
| 有 Python 3.10+（装了 PATH） | 源码版 `start.bat` | 首次约 1 分钟自动装环境；之后秒开；可离线二次启动 |
| 没有 Python | 免安装包 `启动.bat` | 零依赖；自带标准 CPython；不写注册表/不开机启动 |

已覆盖的常见坑：中文/空格路径、假 Python（商店别名）、旧版本 Python、端口被占（6 候选自动切换）、
无 Edge/Chrome（默认浏览器兜底）、联网差（多镜像 + 离线兜底）、断网（已装好后可离线启动）。

## 五、为什么不换 Java（结论：不换）

1. “兼容性极好”的本质是**目标机器要有运行时或自带运行时**。Java 一样要装 JRE 或自带 jlink 运行时，
   并不比“便携 Python 自带解释器”更省事；
2. 换语言 = 后端（FastAPI + SSE + 七工具 + Agent 循环）与整条海报管线全部重写，2–3 周工作量，
   距报名截止（10-22）与比赛（10-31）只剩两周，风险远大于收益；
3. Python 侧的兼容性问题**这次已经逐项修掉并用探针守住**（free-threaded、缺依赖、路径、静默失败等），
   继续加固的边际成本极低；
4. 如果以后想要“exe 双击”体验，可在现有便携包外套一层启动器打包，不需要换语言。

## 六、剩余动作（按优先级）

1. **你本人做最终验收（必做）**：
   - 源码版：双击 `start.bat` → 等浏览器 → 对话页能开；
   - 免安装版：把 `dist\枫客松-小栖-demo-free.zip` 解压到**另一台没有 Python 的电脑**，双击 `启动.bat`，
     走到“能对话 + 能出海报”（这是唯一还没在真实机器上验证过的场景）；
   - 本机预检：`.venv\Scripts\python scripts\selftest_portable.py`。
2. **清理（必做，沙箱删不动，你手动删）**：
   - `dist\_obsolete\`（旧损坏包 + 旧 zip）
   - `.tmp\portable-bad-freethreaded\`（下错的 free-threaded 包）
3. 以后每次改完代码重打包：`scripts\build_portable.bat`（会复用已下载的解释器包；无网也能用离线兜底）。
4. 既定计划不变：M5 点位扩到 30 个 / M8 换实拍参考图 / 桌面快捷方式。
