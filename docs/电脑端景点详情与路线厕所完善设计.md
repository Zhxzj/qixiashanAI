## 4. 路线和厕所的核实流程

### 4.1 分开管理四种证据

1. **原图证据**：文件哈希、来源、图中名称或图标、相邻地标、人工框选范围。像素框只定位原图上的证据，不是地图坐标。
2. **地理匹配**：可靠地理来源、对象身份、WGS84坐标或完整道路几何、坐标精度/局限、匹配时间。禁止仅凭同名或最近距离认定相同。
3. **通行核实**：接入步道、入口、道路连接、台阶和限制条件、资料时间；没有信息时为未知。
4. **现场核实**：实地坐标、采样设备/精度、现场状态与日期；没有现场证据保持 `field_verified:false`。

状态分开保存，不能把“地图数据库有点”写成“已现场核实”，也不能把“用户提交来源”自动写成“准确无误”。

### 4.2 路线更新步骤

- 对照图中主干道、园路和栈道的连接关系，建立“相符、缺失、名称差异、疑似冲突、待确认”记录。
- 现有OSM是地理底图和已有路网基础；必要时在实施中取得有来源的局部数据更新，保留采集时间、原始来源与版本。不在用户日常使用时反复下载整片数据。
- 新增/修正路段必须有可靠地理几何与连接证据。不能把示意图曲线拉伸配准后当作精确步道；不能把靠近或图形相交视为连通，注意桥、层级和端点。
- 图上类别与OSM类型冲突时保留两者和处理理由。未经核实的“栈道”标注不直接成为导航约束，更不能据此推断没有台阶或无障碍。
- 保留“禁步行、私有、施工、条件限制”等过滤及同边接入逻辑。新节点/边应通过局部连通、方向、长度、异常跳点和既有路线回归。
- 核准的补充数据独立存层，记录来源、适用许可和版本，经过构建脚本合成为有效路网；不直接手改生成的 `map.json` 后丢失可复现性。
- 数据升级后路线必须绑定有效路网版本；运行时版本不符则停止旧进度/到点判断并提示重新规划，不能混用新图与旧路径。

现有路网可以继续提供其原有边界内的路线预览；本轮新增、疑似冲突但未核实的边不进入算路图。完整实地导航可用性不由UI升级或编译通过证明。

## 5. 聚焦、选中与导航状态

### 5.1 统一操作入口

地图景点标记、主要景点按钮、搜索结果及参考清单中已经核准的对象，统一调用 `selectPlace(placeId, options)`。旧 `showPlace()` 可保留兼容适配，但不再各自维护一套选择逻辑。

只对有可靠地理点位的对象聚焦；无坐标候选仅打开待核实信息，不移动到猜测位置。点击主要景点时：

1. 记录 `selectedPlaceId`，更新标记/列表高亮，打开详情。
2. 平移至该点并适度放大。初始建议目标级别18，已有更近视图不自动缩小，始终受Leaflet实际最小/最大级别约束；同一对象重复选择不反复动画。
3. 使用平移留白或视图偏移，让目标在未被详情遮挡的可见地图区域内。面状地物代表点标注“不是入口”，不把详情聚焦点当导航入口。
4. 保留当前路径、起终点、途经点、路线版本、定位订阅和进度。

`selectedPlaceId` 是阅读状态；`destination` 只有点击“设为终点”后才变化，并沿用原有取消旧路线、停止旧导航及重新规划流程。地点照片点击只打开大图，不改变地图选择或路线。

### 5.2 定位跟随与恢复

- 用户主动选景点或拖动地图时，暂停“镜头跟随”，防止下一次定位样本把视角拉回本人位置；定位采样和符合精度条件的既有路线判断仍可继续。
- 明确显示镜头跟随已暂停，并提供“回到我的位置/恢复跟随”。只有用户主动操作才恢复镜头跟随，详情关闭不自动跳回本人位置。
- “返回全览”显示当前路线全貌；没有路线时回到已知景区数据范围。它不重置路线、关闭定位或改变起终点；保留“回到景区”和“路线全览”现有含义。
- 关闭详情清除阅读选中态和标记高亮，保留当前视图及路线。到点讲解继续通过原有到点卡呈现，不抢占正在阅读的景点详情。
- 新行程重置清除选中态和未完成详情请求；模式切换清除真实模式临时详情，演示数据不混入真实地图。

### 5.3 并发和页面更新

详情缓存按 `place_id + content_version` 区分。快速从A切换B时取消A请求或使用选择序号丢弃旧响应；A照片迟到或加载失败不能覆盖B。轮询不重建Leaflet实例，不重复聚焦或清空详情；布局变化后调用 `invalidateSize()`，保留中心和级别，避免灰块、偏位或路线丢失。支持 `prefers-reduced-motion`，减少动画时直接切换视图。

## 6. 详情版式与文案

### 6.1 宽窗口与窄窗口

宽窗口在地图卡片内部安排“地图在左、详情在右”，保留原对话和其他功能。建议内部可用宽度达到约720px时并列：地图至少360px，详情约280—320px，中间留白；不足时详情移到地图下方。以实际容器宽度判断，避免只按屏幕宽度导致地图侧栏被挤窄。

详情包含：名称/关闭、照片、简明介绍、详细介绍、资料来源/核实状态、设为起点/终点/途经按钮。图文高度预留，来源可折叠但应可访问；不遮挡Leaflet版权、缩放和比例尺。1366×768和1440×900等桌面窗口重点验证；窄窗口及200%页面缩放无横向溢出。

### 6.2 两层介绍规范

| 部分 | 建议表现 | 内容要求 |
| --- | --- | --- |
| 景点名称 | 标题，约22—26px | 使用核实名称，别名单独说明 |
| 上半简明介绍 `summary` | 较大字号，约20—22px，行高约1.6 | 建议20—40字，说明“这是什么、主要看什么” |
| 下半详细介绍 `detail` | 较小字号，约14—16px，行高约1.7 | **最多200字**，补充历史、建筑、观察要点等有来源的事实，不重述上段 |
| 来源与状态 | 不小于12px，清晰对比 | 可查看资料标题、链接、图片署名、核实日期与缺口 |

“详细最多200字”只计算详细正文，不把标题、来源和按钮塞进正文。以去除首尾和排版空白后的Unicode字符计数（中文、标点和数字均计入），正文超过200不通过内容验收；不能运行时硬截断到半句话。简明20—40字为编辑目标，优先自然准确，不为凑字复述。

两段不重复是事实与表达层面的要求：上段已说的核心定位不在下段换个说法再讲一遍。可用全文相等/明显重复句检测辅助发现，但最终需人工逐条审核，不能以机械词语重合阈值代替语义判断。

只展示核准文本；既有草稿先核查再重写。没有足够证据时简短说明“详细介绍待核实”，不生成历史故事、开放时间或难度等缺失信息。来源表支持每段对应哪些证据，避免“挂一个链接就当全部事实已证实”。

### 6.3 实景照片及放大

- 首版每景点最多一张首图，不新增复杂相册；可点开放大，保持原图比例，不变形。
- 首图显示拍摄对象、作者/来源及必要的拍摄时间说明。历史照片不暗示当前状态；景区泛景照必须标成泛景，不能当特定亭阁或山峰实景。
- 正文预留约4:3图片区域，可适当裁切但记录处理；大图以完整可见为主，支持关闭、Esc和键盘焦点恢复。
- 不具备照片时显示明确的文字占位“照片待补充”，不用合成示例；加载失败只在照片区提示，不阻塞文字、地图、路线按钮。
- 随包提供优化后的展示图和可放大图，按许可保留作者、来源、许可版本、原图标识、取得时间、裁切/压缩说明和哈希。图片许可不混同于代码或OSM数据库许可。
- 不用外部热链作为运行时必需资源，不在线等待素材查询，不开启图片预抓取或地图瓦片批量下载。

## 7. 数据与接口方案（实施前规格）

下列是拟议契约，不表示本次已创建对应代码或文件。实施前按项目AGENTS约定在 `docs/` 记录跨目录接口变更。

### 7.1 建议的数据职责

| 拟议文件/位置 | 职责 |
| --- | --- |
| `app/data/map_places.json` | 稳定应用ID、主要景点分类、显示名/别名、OSM关联、聚焦点、入口引用、各类核实状态 |
| `app/data/place_content.json` | summary、detail、内容版本、逐段资料来源、图片元数据、审核状态 |
| `app/data/map_review.json` | 三图来源、候选及差异、原图像素证据、匹配处理记录和待补项 |
| `app/data/map_overrides.json` | 经核准的地理补充及路网连接资料；与OSM基础快照分开、可复现合成 |
| `web/assets/places/` | 获准随包的实际景点图片，稳定安全文件名 |
| `docs/景点素材来源与核实台账.md` | 人工可审核的来源、许可、对象身份、缺口及核对结论 |

应用ID例如 `qxs-qixiasi`，不使用显示名、数组下标或用户电脑路径作主键。一个景点可关联OSM对象，但关联不自动等于入口或已现场核实。旧演示 `poi_id` 映射独立存储；不能为了让讲解触发而强绑不同对象。

核实状态使用明确的枚举或结构化字段，不只用单一布尔值；至少区分身份/名称、位置、接入/通行、现场、内容与照片许可。允许不同方面独立待补，展示层如实表达。

### 7.2 只读详情接口

- `GET /api/map/places?major=true`：返回主要景点轻量目录、应用ID、名称、可用聚焦点、照片/内容是否可用、状态和版本。
- `GET /api/map/place?place_id=qxs-qixiasi`：返回选中景点的已核准详情和来源、图片路径、核实状态。未知ID返回404；无文案/图片返回结构化缺失状态，不返回伪造内容或整个原始内部台账。
- 静态图片从本机受控相对路径提供；禁止任意文件路径、目录穿越及把素材内部备注直接公开。
- `GET /api/map/osm/data` 保持兼容，按需增加目录/核对版本引用；原始OSM导出与实际有效路网导出应明确区分，补充层来源和许可可追溯。
- 保留既有设施接口字段，新增字段具备向后兼容默认值。设施覆盖、删除、候选转正均先预览，不静默替换用户数据。

接口在本机只读，不调用模型、Wikimedia或其他外部资料服务；外部资料查找发生在整理/构建阶段。图片或资料链接只接受核准的安全协议；正文通过文本节点渲染，外链使用 `noopener noreferrer`，不执行来源文本中的HTML。

原聊天SSE事件、工具注册、模型参数、启动端口和持久化隐私规则保留。本轮不改变游客/账号、模型Key和费用方案。

## 9. 性能、可用性与隐私要求

- 详情不调用模型，不降低现有模型回答质量或消耗额外推理额度。
- 主要目录轻量加载；图片不随高频状态轮询传输，首次选择加载，重复选择可缓存。图片固定尺寸减少布局抖动；不一次解码所有大图。
- 性能以本机EXE、Edge、固定窗口及冷/热缓存分别记录，区分文本和图片。建议本地缓存文字显示P95≤300ms、随包首图P95≤1s作为待实测目标，至少30次交互并记录机器/样本，不能用单次截图宣称达标。
- 若素材体积影响启动，优先优化展示分辨率与编码，保留可读性，不以外部热链增加用户等待。
- 继承WGS84、不重复转换、精度和新鲜度降级规则；景点浏览不向外发送用户定位，也不把精确位置和真实路径加入新文案日志。
- 资料来源中的作者署名保留必要内容，不公开无关个人联系方式；不打包用户本机配置、密钥、素材台账中受限备注或微信临时目录路径。
- 没有网络时本机文字、图片、已有道路和本地规划可用；在线底图失败保留原提示与矢量降级。公共瓦片使用政策继续遵守，不因自动聚焦而批量缓存瓦片。

### 分别签收，避免“编译成功等于全部完成”

- **交互验收**：选点、聚焦、详情、版式、状态隔离及打包通过。
- **内容验收**：按景点逐项签收照片、简介、详述和来源；缺失数量如实列出。A批尽力优先完成，未完成不得笼统声称全部景点照片已齐。
- **地理数据验收**：按新增道路/厕所逐项核实位置与接入。没有新增核准数据时记录“本轮新增0项”和待补项，不把核对清单冒充数据完成。
- **现场验收**：另记录实地精度、道路/入口/厕所开放情况。缺失时标明待完成，不承诺精准实时导航或全园覆盖。
