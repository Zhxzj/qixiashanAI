## 3. 原因分析：已确定的问题和待验证的问题分开

### 3.1 已确定：大门没有预置坐标，当然不会显示

`app/data/map_annotations.json`中两处大门为null，前端仅绘制有坐标的设施。测试还明确断言首次打开大门图标数量为0。

这不是偶发显示故障，而是实现和验收目标偏了：测试证明的是“没有编造大门位置”，没有证明“已经替用户标好大门”。不能因为接口和点选工具可用，就宣布这项完成。

### 3.2 已确定：验收环境没有覆盖用户实际窗口

浏览器测试使用新建无头窗口、隔离用户目录和测试状态。它验证了12个图标可以渲染，也验证了工具操作，但没有检查用户已有窗口的页面版本、当前地图模式、复选框实际状态、脚本异常和屏幕中的可见结果。

现有首屏断言主要检查标记DOM数量，不等于确认12处标记在实际可见地图中清晰可辨。我的交付说明没有把这个证据边界讲清楚。

### 3.3 已确定：界面缺少从数据到显示的可核对状态

页面统计偏重“数据里有多少厕所”，没有同时显示“图层是否开启、已画多少、当前视野内多少、是否初始化失败”。出现用户所说的“一个都没有”时，不能迅速看出消失发生在哪一步。

WC小方块、悬浮名称也不如明显的厕所图标加名称直观；即使技术上渲染，仍需按可识别性验收。

### 3.4 厕所未显示的具体触发原因仍待当前页面复现

目前不能声称已找到唯一根因。应逐项验证，而不是任选一个解释：

- 当前页面是否仍持有之前加载的JS或HTML，前后端构建是否一致。
- 是否处于演示草稿模式；该模式不会绘制OSM设施。
- 浏览器恢复表单状态或已有交互后，厕所复选框实际属性是否关闭。
- 初始化是否在其他请求或脚本异常处提前中断；当前代码的初始化依赖多项请求，失败主要显示为聊天区提示。
- 图层是否真实添加到当前Leaflet实例；标记是否在视野外、被覆盖，或样式未正确应用。

本次尚未读取用户正在看的那个窗口的实时DOM和截图，因此以上都是排查分支，不是已证明的原因。

## 4. 诊改顺序

### 第一步：先在当前实例与页面复现，保存前后证据

以用户正在使用的实例为起点，核对当前页面URL、前后端构建、地图模式、图层开关实际状态、标记数量、可见范围和控制台错误。保留修改前的实际窗口截图与必要诊断信息，不要求用户自己猜版本、填JSON或重新标12个点。

先确定“数据未到前端、绘制未执行、图层被隐藏、视野问题、旧页面资源”中的具体环节，再针对原因修复。不能只另开一个干净测试窗口展示成功。

### 第二步：让12处厕所默认、清晰且可核对地显示

- 继续只使用今天的紫色截图和现有OSM坐标基准，保留T01—T12，不添加旧图候选。
- 首次进入真实地图时默认开启厕所图层；显隐仍可手动操作。
- 使用清晰的厕所图标，合理缩放下显示“厕所T01”等短标签；高缩放下不因聚合或重叠丢失点位。
- 增加“查看全部厕所”，一次操作将12点完整纳入视野。
- 明确区分数据数量、图层绘制数量和视野内数量；数据载入失败时在地图处直接显示错误和重试入口。
- 校对作为可选修正功能，不能成为看到厕所的前提。

### 第三步：把大门任务补成有数据的交付

我先核对现有OSM地物与入口道路关系，整理可证明的大门名称、坐标和依据；不把无名门禁、停车道闸或“北门”直接改名冒充西门/南门。

今天的紫色截图没有明确标出西门、南门，无法仅凭它确定两门准确坐标。能核实的入口应预置上图，不再把空值当完成；仍缺依据的入口应列出具体缺口。确实需要用户确认时，应只针对有根据的候选位置作一次简明确认，而不是把整个标注工作交给用户。

大门点位未核实前，不承诺“各个大门已标全”。位置近似、现场开放及道路接入状态分别注明。

### 第四步：补齐启动、资源和地图初始化的一致性

- 页面显示可核对的程序版本；前后端构建不一致时明确提示加载当前版本。
- 静态资源绑定构建版本，明确处理已有窗口与旧资源，避免让用户靠手动清缓存解决。
- 保留旧包供回退，但正式交付入口和名称清楚区分，不删除用户文件。
- 基础地图、设施和说明信息分开处理加载失败；失败在地图旁可见，不能因一个次要模块失败而使设施悄悄缺失。
- 模式切换时说明当前是否显示真实设施；避免用户误以为演示图就是已完成的设施地图。

### 第五步：按原要求核对照片排版

在实际页面确认缩略图下直接衔接简介和详述，大图下无照片说明；来源、作者、许可只在默认折叠区可查。不靠源码里删除了一个元素就认定视觉验收完成。

### 第六步：改验收标准，再构建交付

必须同时满足：

1. 交付EXE与当前运行的后端、页面、数据版本一致。
2. 打开真实地图即能看到厕所；“查看全部厕所”后12点都位于地图可见范围，截图逐点对照今天原图，不能只数DOM。
3. 大门有已定位图标与来源；未完成的入口如实列出，不以“有校对入口”代替“大门已上图”。
4. 当前用户已有数据和已有窗口场景，以及新用户场景都通过；覆盖重启、已有页面、图层显隐、模式切换和加载失败。
5. 看景点、看设施、看照片不误改路线；图标坐标不为了贴路而移动，路线仍只走真实已有路网。
6. 保留源码测试和EXE检查，但最终附实际成品可见截图、版本及逐项需求结论。
